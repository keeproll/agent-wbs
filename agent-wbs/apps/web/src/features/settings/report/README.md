# features/settings/report — 설정 → 보고서 · 메일 탭(M6-03)

팀장이 보고서 메일의 받는 사람, 메일 서버(SMTP), 발송 기록을 관리하는 탭이다.
주소는 `/settings/report`다.
원본은 `prototype/uiux/Main.dc.html`의 보고서 · 메일 탭(UI-12-04, P L2511-2580, mailVM L6496-6531)과 메일 미리보기 창(P L2725-2741)이다.
서버 쪽 설명은 [apps/api/src/mail/README.md](../../../../../api/src/mail/README.md)에 있다.

## 1. 파일

| 파일 | 하는 일 |
|---|---|
| `ReportMailTab.tsx` | 카드 셋(받는 사람 · 메일 서버 · 발송 기록)과 메일 미리보기 창 |
| `model.ts` | 화면 없는 계산: 상태 이름, 추가 폼·SMTP 폼 검사(원본 문구 그대로), 최근 발송, 요약 |

- 시험: `test/settings-mail-model.test.ts`(계산), `e2e/api-mail.spec.ts`(실제 API · 가짜 SMTP).
- 탭 배지: `SettingsPage.tsx`가 `GET /api/mail/log?status=failed`의 건수(아직 해소되지 않은 실패 수)를 빨강으로 보인다(G§4.9 L344).

## 2. 동작

- **받는 사람 표**: 일간 · 주간 · 주간 보기 · PDF 첨부 · 중지는 누르면 바로 저장한다(원본과 같다).
  - 저장은 공통 `useSave`로 보내고 그 줄의 버전(`updatedAt`)을 함께 보낸다. 다른 탭에서 먼저 바꿨으면 충돌 창이 뜬다.
  - 일간 · 주간을 모두 끄면 서버가 자동으로 「중지」로 바꾼다. 구독이 없으면 「다시 받기」는 눌리지 않는다.
- **받는 사람 추가**: 누르기 전에 원본 순서대로 검사한다(비었음 → 형식 → 중복(대소문자 무시) → 구독 없음).
  - 입력 중인 주소·이름이 있으면 다른 탭으로 가기 전에 묻는다(편집 보호).
- **메일 서버(SMTP)**: 「SMTP 설정 / 수정」을 누르면 폼이 열린다. 보안 방식을 고르면 포트가 기본값(587 · 465 · 25)으로 바뀐다.
  - 비밀번호 칸을 비워 두면 저장된 비밀번호를 그대로 쓴다. 비밀번호는 화면에 다시 나오지 않는다.
  - 「연결 확인」 결과(정상 / 실패 · 확인 시각 · 오류)는 서버가 적은 값을 보인다. 실패면 받는 사람 카드 위에 「메일 서버 연결 실패」 배너가 뜬다.
- **발송 기록**: 최신 40건(원본과 같은 한도). 「전체 / 실패만」으로 거른다.
  - 아직 해소되지 않은 실패가 있으면 주황 배너와 「실패 건 모두 다시 보내기」가 보인다. 행마다 「다시 보내기」도 있다.
  - 「수락 여부 불명」이 섞여 있으면 「두 번 받을 수 있다」는 안내를 함께 보인다(contracts §4.4).
- **외부 수신자(Q-13 결정 A)**: 받는 사람 행의 「외부」 단추와 추가 폼의 「외부 수신자」 확인란으로 정한다.
  - 켜면 일간이 꺼지고 막히며, 주간 보기는 「보고용」, PDF 첨부는 켜진 채로 고정된다(서버가 같은 규칙을 지킨다).
  - 외부 수신자 메일에는 앱 링크와 내부 경로가 없다. 전체 내용은 PDF로 본다. 왜: 링크는 같은 PC · 같은 네트워크에서만 열린다(G L1052).
  - 발송 기록의 「보기」 칸에 「외부」 표가 붙는다. 미리보기 창에는 「외부 수신자 — 앱 링크 없이 보고용 본문과 PDF 첨부로 보냅니다」 안내가 뜨고 보기 전환이 없다.
  - 보고서 화면의 「메일로 보내기」에서 일간 보고서이면 외부 수신자는 고를 수 없다(「일간 보고서는 외부 수신자에게 보내지 않습니다」).
- **다시 보내기 사유**: 원본처럼 「다시 보내기 (ML-0001)」로 남는다. 괄호 안은 다시 보낸 실패 기록의 표시 번호다.
- **메일 미리보기**: 서버가 실제 발송과 같은 함수로 만든 HTML을 받아 `sandbox` iframe에 보인다(스크립트 실행 안 됨). 주간 · 기간 보고서는 팀장용 ↔ 보고용을 바꿔 볼 수 있다.

## 3. 원본과 다른 점

| 무엇 | 왜 |
|---|---|
| 「Mock: SMTP 인증 실패 · 정상 복구」 버튼 없음 | 실패는 실제 연결 확인 · 발송 결과로만 생긴다(UAT-POLICY-05, D-17 · D-23). 시험은 가짜 SMTP 서버의 응답 방식을 바꾼다 |
| 발송 상태에 「대기 · 보내는 중 · 실패 · 15분 후 재시도 · 실패 — 수락 여부 불명」이 더 있음 | 원본은 누르는 즉시 「발송됨 / 실패」였다. 제품은 서버 발송 큐로 보낸다(data-model §3.7) |
| 「테스트」를 누르면 「발송 대기열에 넣었습니다」 안내 | 실제 발송은 worker가 한다. 결과는 발송 기록에서 바뀐다 |
| 발송 기록 「시각」 칸 아래에 발송 표시 번호(ML-0001)를 작게 보임 | 원본은 번호를 사유 「다시 보내기 (ML-0001)」에서만 보인다. 그 번호가 어느 행인지 찾을 수 있게 했다 |
| 받는 사람 행 · 추가 폼에 「외부」 단추, 발송 기록에 「외부」 표, 미리보기에 외부 안내 | 원본에는 외부 구분이 없다(원본 상급자 RC-2는 「보고용 + PDF」일 뿐이다, P L3640). Q-13 결정 A(외부 수신자는 링크 없이 PDF만)를 지키려고 열을 새로 만들지 않고 받는 사람 칸 안에 단추 하나만 더했다 |

## 용어

| 용어 | 뜻 |
|---|---|
| SMTP | 메일을 보내는 표준 방식(메일 서버) |
| 발송 큐 | 보낼 메일을 적어 두는 서버의 작업 표. worker가 차례로 보낸다 |
| 해소되지 않은 실패 | 같은 보고서 · 같은 사람에게 보낸 마지막 발송이 실패인 것 |
| 수락 여부 불명 | 보냈지만 메일 서버가 받았는지 모르는 상태. 다시 보내면 두 번 받을 수 있다 |
| sandbox iframe | 안의 스크립트·양식이 동작하지 않게 막은 작은 창 |
| 외부 수신자 | 회사 밖 · 다른 네트워크에서 메일을 읽는 사람. 링크 없이 보고용 + PDF만 받는다(Q-13 결정 A) |
