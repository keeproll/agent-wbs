# 보고서 상태 이력 (M6-01)

보고서는 기간 끝 시점(T)의 상태를 되살려 보여 준다(owner 2026-11-27 아이템 13, G L375). 이 문서는 「어떤 변경이 T 전인가」를 정하는 규칙과 그 근거를 적는다.

## 1. 용어

- **이력**: 보고서가 읽는 표의 행이 바뀔 때마다 남기는 행 전체 기록(`state_log`·`global_log`, 마이그레이션 0036). 기록 대상 목록은 `tracked.ts` 한 곳에 있다.
- **커밋 시계 값(stamp)**: 쓰기 트랜잭션마다 커밋 직전(또는 그보다 이르게) 매기는 값. 커밋 순서대로 커지고 줄지 않는다(`log_clock`).
- **실제 커밋 시각**: DB가 기록한 진짜 커밋 시각(서버 설정 `track_commit_timestamp=on`, `pg_xact_commit_timestamp`).
- **정리(settle)**: 커밋된 트랜잭션의 두 값을 `commit_real`에 옮겨 적는 단계(0037 `awbs_settle_commits`). 보고서 기준점과 worker가 부른다.
- **관측 시각(observed_at)**: 정리가 그 트랜잭션을 「커밋됨」으로 처음 본 시각.

## 2. 「T 전」 규칙

한 변경(이력 행)은 아래가 **모두** 참일 때만 T 시점 상태에 들어간다.

1. 커밋 시계 값 < T.
2. 실제 커밋 시각 < T. 실제 커밋 시각을 모르면 관측 시각 < T.

왜 두 가지인가:
- 커밋 시계 값만 보면, 제약 트리거를 일찍 실행해(`SET CONSTRAINTS ALL IMMEDIATE`) 값을 먼저 받고 늦게 커밋한 변경이 T 전으로 잘못 들어간다(재리뷰 3).
- 실제 커밋 시각만 보면, PC 시계가 뒤로 갈 때 「그때 만든 보고서 = 나중에 다시 만든 보고서」가 깨진다. 커밋 시계 값이 순서와 결정성을 맡는다.

## 3. 실제 커밋 시각을 모를 때 — 「지어내지 않는다」 (재리뷰 4)

**언제 모르나:** 실제 커밋 시각 기록이 꺼져 있던 때의 커밋, 기록에서 지워진 아주 오래된 커밋.

**하지 않는 것:** 커밋 시계 값으로 실제 커밋 시각을 **채우지 않는다**. 커밋 시계 값은 커밋보다 먼저 매겨질 수 있어, 채우면 T 뒤에 확정된 변경이 T 전으로 들어간다(재리뷰 4 조건 B).

**아는 것:** 그 커밋은 「커밋 시계 값 뒤, 관측 시각 전」에 일어났다.
- 커밋 시계 값은 커밋 전에 매긴다.
- 정리는 이미 커밋된 트랜잭션만 옮겨 적는다(`pg_xact_status = 'committed'`, 부른 쪽 자신의 커밋 전 트랜잭션은 제외 — 재리뷰 4 조건 A).

**T와 견준 결과 세 가지:**

| 경우 | 판정 | 보고서 |
|---|---|---|
| 관측 시각 < T | T 전에 확정된 것이 확실 | 넣는다 |
| 커밋 시계 값 ≥ T | T 뒤 | 넣지 않는다 |
| 커밋 시계 값 < T ≤ 관측 시각 | **알 수 없음** | 넣지 않고 「경계 불확실 n건」으로 센다 |

**결정: 넣지 않고(보수적) 건수를 표시한다.**
- 왜 넣지 않나: 확정됐는지 모르는 변경을 넣으면 그때 없던 상태를 보고서가 지어낼 수 있다. 보고서는 고칠 수 없으므로 잘못 넣은 값은 영원히 남는다.
- 왜 표시하나: 빼기만 하면 팀장이 빠진 것을 알 수 없다. 건수를 스냅샷 `basis.uncertain`에 저장하고 화면 머리에 「경계 불확실 n건 — …」으로 보인다.
- 왜 오래 남지 않나: 기록이 켜진 서버에서는 정리가 짧은 주기(worker 20초, 보고서마다)로 돌아 관측 시각이 커밋 직후다. 그래서 「알 수 없음」 구간은 기록이 꺼져 있던 때의 경계 근처로 좁다.

**기록이 꺼진 서버:** 정리 함수는 `track_commit_timestamp`가 꺼져 있으면 `55000`으로 거부한다(보고서 생성도 실패). 조용히 대체하지 않는다. `compose.yaml`과 시험 DB 준비(`scripts/test-db-setup.ts`)가 이 설정을 켠다.

## 4. 남는 오차

- 실제 커밋 시각·관측 시각은 벽시계다. PC 시계가 d초(이 PC ≈2.3초) 뒤로 가면 경계 근처 d초 안의 커밋 분류가 어긋날 수 있다. 같은 T로 다시 만들면 언제나 같은 결과다(결정성).
- 관측 시각은 실제 커밋보다 늦다(정리 주기만큼). 그래서 「알 수 없음」 판정은 실제보다 넓을 수는 있어도 좁지는 않다(보수적).
