# apps/api/src/mail — 보고서 메일(M6-03)

보고서를 HTML 메일로 보내는 서버 부분이다.
SMTP 설정, 받는 사람, 메일 본문 만들기, 발송 큐, 발송 worker가 여기 있다.
낯선 말은 맨 아래 [용어](#용어)에 모았다.

- 근거: 가이드 G§4.11 L398-408(메일 발송), §8.5(API 표), §9.6-6 L1049-1052(구현 규칙), contracts §2.3·§4.4, data-model §3.7.
- 실제 메일 서버에는 연결하지 않았다. 시험은 로컬 가짜 SMTP 서버(`e2e/fakes/smtp.ts`)로 한다.
  - 왜: 어떤 SMTP 계정을 쓸지는 owner 결정 전이다(Q-13).

## 1. 파일 지도

| 파일 | 하는 일 |
|---|---|
| `routes.ts` | API 경로 등록(계약 `settings.ts`의 메일 operation 13개) |
| `settings.ts` | SMTP 설정 조회·저장·연결 확인, 받는 사람 추가·변경·삭제 |
| `secret.ts` | SMTP 비밀번호 암호화 보관과 꺼내기 |
| `render.ts` | 메일 제목·HTML·text/plain 만들기(미리보기와 발송이 함께 씀) |
| `queue.ts` | 발송 큐에 넣기(정기·테스트·수동·다시 보내기), 발송 기록 목록, 대시보드 알림 |
| `deliver.ts` | 발송 worker(찜하기 → SMTP → 기록), 재시작 정리 |
| `smtp.ts` | SMTP 한 번 보내기·연결 확인, 결과 분류(수락 / 확실한 실패 / 수락 여부 불명) |

## 2. 한 통이 나가는 길

1. 정기 보고서가 생기면 같은 트랜잭션에서 구독자를 큐(`mail_outbox`)에 넣는다(`reports/service.ts` → `enqueueReportMail`).
   - 큐에 넣기만 하고 SMTP는 부르지 않는다.
   - 왜: 메일 서버 오류가 보고서 생성을 실패시키면 안 된다(G L1050).
   - 기간 지정 보고서는 자동으로 보내지 않는다. 「메일로 보내기」(수동 발송)로만 보낸다(G L401).
2. worker가 보낼 차례인 줄을 `sending`으로 바꾸고 **먼저 커밋한다**(찜하기).
   - `for update skip locked`로 찜하므로 worker가 둘이어도 한 줄은 한 번만 나간다.
3. 트랜잭션 밖에서 SMTP를 부른다.
4. 결과를 그 줄과 `mail_log`(추가 전용 기록)에 적는다.

예: 팀장이 일간·주간을 모두 구독하면, 월요일 07:00에는 일간 1통·주간 1통이 큐에 들어간다.

## 3. 결과별 처리

| SMTP 결과 | 상태 | 그다음 |
|---|---|---|
| 서버가 수락(250) | `accepted` | 끝 |
| 수락되지 않은 것이 확실(연결 실패, 로그인 거부 535, 명시적 거부 4xx·5xx, SMTP 미설정) | 첫 실패면 `retry_wait`, 자동 재시도 뒤에도 실패면 `failed` | 15분 뒤 같은 줄을 **한 번만** 다시 보낸다 |
| 본문을 보낸 뒤 응답을 못 받음(timeout·연결 끊김) | `unknown` | 자동으로 다시 보내지 않는다 |
| 보내는 중 worker가 죽음 | (`sending`으로 남음) → 다음 시작 때 `unknown` | 자동으로 다시 보내지 않는다 |

- 왜 unknown은 다시 보내지 않나: 서버가 이미 받았을 수 있다. 가이드는 메일이 두 번 나가면 안 된다고 했다(G§9.6-6, contracts §4.4).
  - 팀장은 발송 기록의 「수락 여부 불명」 안내를 보고 직접 「다시 보내기」를 누른다.
- 어떻게 「본문을 보냈는지」 아나: nodemailer 오류는 연결 실패와 응답 유실을 둘 다 `command: 'CONN'`으로 알린다(직접 확인함).
  - 그래서 메일 원문을 넘기는 스트림이 처음 읽힌 순간(서버가 DATA에 354로 답한 뒤)을 기록해 둘을 가른다(`smtp.ts`).
- failed·unknown이 남아 있으면 대시보드 알림(`alerts`, 키 `mail:failed`)을 연다. 모두 해소되면 닫는다.
  - 「해소」는 같은 보고서·같은 사람에게 그 뒤에 다시 보낸 발송이 있다는 뜻이다.

## 4. 멱등 키와 발송 번호

- 큐 한 줄의 키는 「보고서 ID + 받는 사람 ID + 발송 번호(`try_no`)」다(DB 고유 제약).
- 같은 보고서를 같은 사람에게 다시 보내면 발송 번호가 하나 늘어난 **새 줄**이 생긴다.
  - 왜: 이전 발송의 결과(실패·불명)를 지우지 않아야 「몇 번 나갔을 수 있는지」 알 수 있다.
- 15분 자동 재시도는 새 줄이 아니라 **같은 줄**을 다시 보낸다(`retry_wait → sending`, `retried=true`).
- 이미 해소된 실패 줄에 「다시 보내기」를 누르면 409 `INVALID_TRANSITION`이다. 두 탭에서 동시에 눌러도 한 번만 나간다.
- 줄마다 발송 표시 번호 `ML-0001`(`log_key`)이 있다. 프로젝트 카운터(`counters` kind `mail_log`)로 매기며, 초기화하면 1부터 다시 시작한다.
  - 다시 보내면 사유가 원본처럼 「다시 보내기 (ML-0001)」이다. 어떤 실패 기록을 다시 보냈는지 가리킨다(P resend L4970).

## 5. 메일 본문 규칙(G L1049)

- 표(`<table>`) 레이아웃, 모든 모양은 인라인 스타일, 폭 640px.
- `<style>`·외부 CSS·class·flex/grid·외부 이미지·스크립트·웹 폰트를 쓰지 않는다.
  - 왜: Outlook·Gmail 같은 메일 앱은 이것들을 지우거나 무시한다.
- 글꼴 순서: `'Pretendard GOV','Apple SD Gothic Neo','Malgun Gothic',sans-serif`.
- 서식 없는 본문(text/plain)을 함께 보낸다(multipart/alternative).
- 본문은 보고서 전체가 아니라 요약이다(G L403).
  - 팀장용: 핵심 지표 4개 + 팀장 확인 필요 · 완료한 Task · 진행 중 · QA 실패 · 일정 재조정 · 다음 예정.
  - 보고용: 핵심 지표 4개 + 요약 · 주요 완료 항목 · 위험 · 이슈 · 다음 계획. Task ID 같은 내부 용어가 0건이다.
  - 지표 이름과 보고용 요약 · 위험 문장은 **원본 메일 문구**(P mailHtml L4006-4014) 그대로다.
    - 팀장용 지표: 완료 (기간) · 완료율 (작업량) · 완료 예상 (vN) · 가동률(중단 N회 / 중단 없음).
    - 보고용 지표: 완료 · 진척률 · 완료 예상일 · 목표일 대비.
    - 왜: 원본 프로토타입이 완료 기준이다(coordinator 판단 2026-11-27). 화면 보고서의 지표 이름 · 문장과는 조금 다르다.
  - 숫자는 화면 보고서와 같은 계산(shared `reportFigures`, `internalKpis`·`externalView`가 쓰는 것)에서 온다. 그래서 화면 · 메일의 숫자가 같다.
- 일간 보고서는 항상 팀장용이다(G L402).
- 「Agent WBS에서 전체 보고서 보기」 링크는 접속 주소(`app_settings.app_url`, 설정 → 알림)가 있을 때만 넣는다.

## 6. SMTP 설정과 비밀번호

- 비밀번호는 AES-256-GCM으로 암호화해 `secrets` 표에 둔다(키는 환경 변수 `AWBS_SECRET_KEY`). 형식은 GitHub 토큰 보관과 같다.
- API 응답·로그·내보내기에는 `pwSet`(등록 여부)만 나간다. 비밀번호 끝자리(`last4`)도 남기지 않는다.
  - 왜: 토큰과 달리 비밀번호는 일부만 보여도 추측에 도움이 된다.
- 편집 버전은 `settings_version`이다. 연결 확인 결과(정상/실패·시각·오류)는 같은 줄에 적지만 편집 버전을 올리지 않는다.
  - 왜: 수정 폼을 열어 둔 채 「연결 확인」을 눌렀다고 저장이 409 충돌이 되면 안 된다.
- 보안 방식은 원본 값 셋 중 하나다: `STARTTLS` · `SSL/TLS` · `없음`. 그 밖의 값은 400.

## 7. 초기화와 경합(data-model §5)

- 「설정 유지」 초기화: SMTP·받는 사람은 남고 큐·발송 기록은 지운다. 기본(설정 삭제): 모두 지우고 SMTP 비밀번호도 지운다(`reset_project`).
- worker의 찜하기와 기록은 모두 세대 번호(epoch) 잠금 안에서 한다.
  - 초기화가 먼저 끝났으면 옛 세대로 찜할 수 없다(AW001 → 아무것도 보내지 않음).
  - 이미 SMTP로 보낸 뒤 기록하려는데 세대가 바뀌었으면 결과를 버린다. 지워진 발송 기록을 새 세대에 되살리지 않는다.
- 이미 나간 메일은 회수할 수 없다. 그래서 초기화 확인 화면이 「보내는 중」 건수(`reset-preview`의 `sending.mail`)를 미리 보인다.

## 8. worker

- `runner/worker.ts`에 메일 주기(10초)를 따로 두었다. 시작 때 한 번 `recoverMail`(보내다 죽은 줄 → unknown)을 부른다.
  - 왜 따로인가: SMTP 응답을 오래 기다려도 Runner 생존 감시(20초 주기)가 밀리지 않게 하기 위해서다.
- 한 번에 최대 20통을 찜한다. 운영 SMTP 응답 대기는 60초, 연결 확인은 15초다.

## 9. M6 통합에서 붙일 연결 지점

M6-01(보고서 화면) · M6-02(PDF)가 끝난 뒤 M6 통합에서 붙인다. 지금은 연결 지점만 준비했다.

- **PDF 첨부(M6-02)**
  - 붙이는 곳: `deliverMail(pool, epoch, { pdf })`의 `pdf: (reportId, view) => Promise<Buffer | null>`. worker(`runner/worker.ts` 메일 주기)에서 넘긴다.
  - 이미 있는 것: 큐 줄의 `pdf`(첨부 여부, 일간은 항상 false), 파일 이름 `pdfName()`(예: `RPT-W-261027_보고용.pdf`), 미리보기 응답 `attachment`.
  - PDF를 만들지 못하면 보내기 전 실패(`rejected`)로 처리한다. 수락되지 않은 것이 확실하므로 15분 재시도 규칙을 따른다.
  - 지금은 `pdf`를 넘기지 않아, 받는 사람의 「PDF 첨부」가 켜져 있어도 HTML만 나간다.
- **보고서 화면의 「메일 미리보기 · 메일로 보내기 · 발송 기록 펼침」(M6-01 화면, G L405)**
  - 미리보기: `GET /api/reports/:reportId/mail/preview?view=&to=`. 화면 부품은 `features/settings/report/ReportMailTab.tsx`의 `MailPreview`(export)를 그대로 쓸 수 있다.
  - 메일로 보내기: `POST /api/reports/:reportId/mail {recipientIds, view?}`. 기본 선택은 그 종류 구독자(P openSend L4975), 보기는 「모두 팀장용 / 모두 보고용 / 수신자 기본값」(`view` 생략).
  - 발송 기록 펼침: `GET /api/mail/log` 결과를 `reportId`로 거른다.
- 실제 SMTP 계정 연결(Q-13).

## 용어

| 용어 | 뜻 |
|---|---|
| SMTP | 메일을 보내는 표준 방식(메일 서버). 응답 번호 2xx 성공, 3xx 계속, 4xx 일시 실패, 5xx 영구 실패 |
| 큐(outbox) | 보낼 메일을 적어 두는 작업 표. worker가 차례로 꺼내 보낸다 |
| 찜하기(claim) | worker가 한 줄을 「내가 보낸다」고 표시하고 커밋하는 것 |
| 멱등 키 | 같은 요청이 두 번 와도 한 번만 처리되게 하는 고유 키 |
| unknown(수락 여부 불명) | 보냈지만 서버가 받았는지 모르는 상태. 화면에는 「실패 — 수락 여부 불명」 |
| epoch(세대 번호) | 초기화할 때마다 1씩 느는 번호. 초기화 전 작업이 초기화 뒤 데이터를 건드리지 못하게 막는다 |
| multipart/alternative | HTML 본문과 글자만 있는 본문을 함께 담는 메일 형식. 메일 앱이 읽을 수 있는 쪽을 보인다 |
| text/plain | 서식 없이 글자만 있는 본문 형식 |
| fake(가짜) SMTP | 실제 메일 서버 대신 시험에서 쓰는 로컬 서버. 메일을 밖으로 내보내지 않는다 |
