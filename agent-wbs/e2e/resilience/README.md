# M8-02 장애·부하 시험

`agent-wbs` 폴더에서 `pnpm test:resilience`를 실행한다.
Docker(전용 데이터베이스를 실행하는 도구)와 두 프로젝트의 설치된 의존성이 필요하다.
이 명령은 무료 fake(외부 서비스를 대신하는 가짜 실행기)만 쓴다.
Claude·Codex 유료 호출과 실제 GitHub·SMTP·Telegram 쓰기는 없다.

## 다른 자료를 건드리지 않는 방법

명령마다 `awbs-m802-<임의 번호>` 전용 컨테이너를 만든다.
Debian PostgreSQL 16을 사용한다.
`track_commit_timestamp=on`으로 실제 데이터 저장 완료 시각을 기록한다.
보고서가 저장 도중의 자료를 잘못 포함하지 않게 하려는 설정이다.

기존 환경 파일의 DB(데이터베이스) 주소는 읽지 않는다.
빈 로컬 포트를 한 번 선택해 고정한다.
Docker가 포트를 다시 배정하면 DB 재시작 시험이 잘못된 주소로 접속하기 때문이다.
시작은 TCP(프로그램 사이의 네트워크 연결) 접속 가능 여부를 확인한 뒤 진행한다.
초기화 도중 잠깐 켜지는 임시 DB를 준비 완료로 오해하지 않으려는 것이다.
시험이 성공하거나 실패하면 `docker rm -f -v <전용 이름>`으로 컨테이너와 익명 볼륨을 함께 지운다.

## 무엇을 확인하나

각 시험은 Task 200개를 만든다.
실행 명세·등급·체크리스트·산출물·추정 시간도 함께 넣는다.
그 뒤 실제 API(프로그램 사이의 요청 창구)로 실행을 요청한다.
같은 Task의 요청 8개가 겹쳐도 추가 실행 요청은 만들지 않아야 한다.
32개 작업 수령 요청이 경합해도 실행 세션은 24개여야 한다.
사용 중인 슬롯(동시 실행 자리를 세는 단위)도 24개여야 한다.

- 동시 부하: 같은 시도 시작을 8번 다시 보내도 시도는 하나다.
- DB 강제 재시작: Task 변경을 저장 완료하기 전에 DB를 즉시 중지한다. 목록은 503을 반환해야 한다. 시작 뒤에는 미완료 변경을 되돌리고 기존 작업 번호표와 실행 상태를 유지해야 한다.
- 결과 재전송: outbox(먼저 디스크에 저장하는 전송 대기함)를 다시 연다. 저장한 결과를 전송한다. 서버가 저장한 직후 응답을 잃어도 재전송으로 후속 QA(품질 검증)를 두 번 만들면 안 된다.
- Runner 강제 종료: 실제 Runner 시험 프로세스에 SIGKILL(정리 기회 없이 즉시 끝내는 신호)을 보낸다. 자손 프로세스가 남아 있음을 확인한다. 공용 복구 코드가 자손을 끝낸 뒤에만 보유를 해제한다.
- PC 변경: 이전 Task 시도를 중단한다. 기존 PC의 미확인 보유를 남긴다. 외부 작업은 `reconcile`(실제 결과를 대조해야 하는 상태)로 남긴다. 이전 보유가 닫혀도 외부 쓰기 관문은 자동으로 열리지 않아야 한다.

시간이 지났다는 이유만으로 프로세스가 끝났다고 판단하면 같은 일이 두 번 실행될 수 있다.
그래서 종료 증거 전에는 슬롯을 반환하지 않는다.
결과를 확인하지 못한 시도는 `interrupted`로 남긴다.
성공·실패나 QA 판정을 만들어 내지 않는다.
감시 시험의 기준 시각만 앞당긴다.
실제 대기는 상태·파일·프로세스 종료를 확인하는 조건 대기로 한다.

## 응답 시간 판정

각 상황에서 다음 네 동작을 각각 20번 잰다.
목록·Runner 상태·보고서 생성은 같은 회차에 함께 요청한다.
보고서 열기는 생성된 문서를 받는 시간이다.
응답 본문을 다 받은 시간까지 포함한다.
예열 값을 제외하지 않는다.

| 동작 | p95 목표 |
| --- | ---: |
| Task 200개 목록 | 1,000ms 이하 |
| Runner 상태 | 1,000ms 이하 |
| 보고서 생성 | 2,000ms 이하 |
| 보고서 열기 | 2,000ms 이하 |

이 수치는 M8-02 조정자 확인으로 정했다.
기존 보고서 시험의 2초 기준을 유지했다.
목록과 Runner 상태는 1초 기준으로 확인받았다.
p95는 시간을 작은 순으로 놓았을 때 95% 지점의 값이다.
20개 측정에서는 19번째 값으로 판정한다.
한 번의 빠른 응답만 보고 성능이 충분하다고 판단하지 않으려는 것이다.

벽시계가 뒤로 가도 측정 시간이 줄어들지 않도록 `performance.now()`를 쓴다.
이것은 시간이 앞으로만 흐르는 단조 시계다.
명령 마지막의 `M8-02 측정값`에는 개별 측정값·p95·기준을 JSON(기계가 읽는 자료 형식)으로 출력한다.

화면 렌더링과 실제 Agent의 CPU·메모리 사용량은 이 명령의 측정 대상이 아니다.
화면 인수는 M8-01이다.
실제 CLI(명령줄 프로그램) 관측은 M8-04다.
