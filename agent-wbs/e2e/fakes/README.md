# 가짜 Runner 시나리오

가짜 Runner(Agent를 실제로 실행하는 대신 정해진 결과를 보고하는 시험 도구)는 실제 HTTP 서버와 PostgreSQL 데이터베이스를 사용한다. Claude·Codex 유료 호출과 실제 개발 프로세스 실행은 없다. 예를 들어 재부팅은 새 부팅 식별자를 서버에 보고하며, 서버가 기존 시도를 중단시키는지 확인한다.

`runner.ts`는 `agent-runner/src/api`의 생성된 계약과 기존 HTTP 클라이언트만 사용한다. 서버 내부 함수와 데이터베이스를 직접 부르지 않는다. 테스트 준비 파일 `test/scenario.ts`만 빈 시험 데이터베이스를 만들고 초기 자료·인증 정보를 넣는다. 팀장 동작은 실제 HTTP 요청으로 수행하며, 서버 감시 시간은 준비 코드에서 앞당긴다. 그래서 연결 끊김마다 몇 분씩 기다리지 않아도 같은 서버 판정을 확인할 수 있다.

## 실행

`agent-wbs` 폴더에서 자기 전용 PostgreSQL 컨테이너 주소를 지정한다. 아래 이름의 데이터베이스와 `_runner_scenario`가 붙은 데이터베이스는 실행할 때 지우고 다시 만들므로 기존 자료가 없는 전용 주소만 쓴다. 이름은 기존 안전 검사에 맞게 `awbs_test_`로 시작해야 한다.

```sh
TEST_DATABASE_URL=postgresql://postgres:시험비밀번호@127.0.0.1:26709/awbs_test_m209 pnpm test:scenario -- runner-basic
```

다른 작업의 컨테이너나 포트를 공유하지 않는다. 시험이 끝나면 직접 만든 컨테이너를 삭제한다. `pnpm test`는 데이터베이스 없는 일반 검사이고, 위 시나리오는 별도 명령으로 실행한다.

## 확인하는 내용

| 가이드 번호 | 실제 확인 |
| --- | --- |
| 6 | Claude 개발 → Codex 품질 검증(QA) 실패 → 생각 깊이(Effort) 상향 재작업 → 재검증 통과. 병합·완료는 범위 밖이다. |
| 8 | 연결 끊김 → 메시지 전달 실패 → 재연결 → 같은 메시지 재전송 → 수신 확인. |
| 9 | 재부팅 → 기존 시도 중단 → 종료 증거 없는 재개 거절 → 증거 제출 뒤 같은 등급의 새 시도. |
| 10 | Claude 한도 도달 → Claude만 실행 보류 → 리셋 뒤로 일정 이동 → 사용량 리셋 후 실행 허용·일정 복구. |
| 보충 | 메시지 중복 조회·중복 수신 확인 후에도 메시지는 하나이고, 수신 확인을 업무 완료로 바꾸지 않는다. |

선행 서버 기능이 빠지면 해당 테스트는 실패한다. 데이터베이스를 직접 바꿔 시나리오를 성공시키거나 실패를 건너뛰지 않는다. M2 통합 전에는 6번의 첫 자동 검사 자리표시와 8번의 연결 감시 연동 누락을 이 명령으로 재현할 수 있다. 검사 결과와 상세 재현은 별도 작업 보고서에 기록한다.
