# M1-01 구현·검증 기록

2026-11-25, `keeproll/m1-01-db`. 최종 커밋 해시는 worker 완료 메시지에 기록한다.

## 구현

- `src/schema.ts`: data-model §2의 테이블 전체와 counters, verification_invalidations, defect_events를 포함한 99개 테이블. UUID/FK, enum, Task 명세의 task PK, CHECK, 부분 unique, nullable 여부를 고정했다.
- Drizzle 생성 SQL과 snapshot을 커밋한다. `0001`은 권한·추가 전용·갱신 시각·holds·프로젝트 참조·초기화 함수의 custom SQL이다. `0002`는 상대 경로 CHECK 수정, `0003`은 Task 명세의 PK 변경이다. PK 변경의 Drizzle 생성 SQL은 실행 순서를 검토·수정했다.
- `awbs_app`: NOLOGIN 앱 그룹 역할, 테이블 SELECT/INSERT/UPDATE와 시퀀스 사용만 부여. 추가 전용 테이블의 UPDATE와 모든 테이블의 DELETE/TRUNCATE를 회수했다. 트리거도 덮어쓰기와 일반 DELETE를 거부한다.
- holds는 §2.5-1의 slot_state/lock_state만 저장한다. held Task·충돌 묶음 unique, 닫힌 행 불변, 슬롯 해제 증거, 인계 시 슬롯 없음, 슬롯·잠금 전이를 강제한다.
- `reset_project(expected_epoch, confirm_name, keep_settings, reset_actor)`: epoch FOR UPDATE, 프로젝트 이름 확인, 미해제 보유를 정리 payload에 보존, 파일 삭제 큐·Runner 명령, FK 순서의 프로젝트 삭제, 설정 유지/삭제, epoch 증가와 reset_log 기록을 같은 트랜잭션으로 처리한다. GitHub 연결과 해당 secret 및 인증 정보는 유지한다. 기준 커밋이 없으면 저장소 정리 정보는 명령에 넣지 않는다.
- `lock_epoch(expected_epoch)`: 앱 변경 트랜잭션의 첫 문장에서 호출할 FOR SHARE 잠금 함수. PostgreSQL의 FOR SHARE에는 UPDATE 권한이 필요하므로 앱에 epoch 수정 권한을 주는 대신 이 함수를 제공한다.
- system seed: 진행률 Q-03, 재시도 2/재작업 3 Q-04, CLI×모델별 effort Q-06 74개 매핑, G §5.2-1 분할 기준·§7.3 실행 정책·§4.14 알림 규칙·§4.13 야간/재시도 기본값. 신규 모델 허용·실제 가용성·운영 관측 등급은 만들지 않는다. Claude 모델별 CLI 동작과 gpt-5.5 가용성은 미확인(null)으로 보존한다.
- demo seed: P의 12 Task·Phase/Work Package·의존성·명세·체크리스트·추정치와 SUB_MOCK 10개를 별도 fixture에서 읽는다. 명시 URL과 실제 접속 DB 양쪽이 로컬 `awbs_test_` 안전장치를 통과해야 하며, 비어 있는 프로젝트에서만 실행한다. Mock 가동률 0.6/재조정 임계값 1은 demo에만 넣는다.

## 요구사항별 테스트 대응

`test/schema.db.test.ts`의 테스트 이름으로 추적한다.

| 요구사항 | 테스트 |
|---|---|
| 전체 테이블·column/type/nullability drift | all planned tables and Drizzle columns match the migrated database |
| 직전 migration에서 데이터 보존 upgrade·반복 적용 | previous migration upgrades with data preserved and repeated migrate is inert |
| system seed 멱등·Q-03·Q-04·Mock/미승인 값 제외·기본 정책 | system seed is repeatable, owner Q-03/Q-04 values match, no Mock or unapproved defaults |
| Q-06·ultra/미확인 미매핑 | Q-06 CLI × model mapping, unknown availability and ultra remain unmapped |
| singleton·제목·우선순위·enum·domain·FK·의존성·추정 범위 | singleton, title, priority, enums, domains, FK and dependency constraints reject invalid writes |
| bootstrap·입력 버전·열린 알림·정기 보고서·멱등 키·수신자 unique | unique bootstrap, input version, notify event, report period and idempotency keys |
| 열린 시도 1개·종료 불변·상대 경로 | open attempt unique and terminal attempt immutable |
| holds unique·미확인 슬롯 잠금·해제 증거·닫힌 행 | holds keep task/conflict locks with unconfirmed slots, require release proof and never reopen |
| 인계 후 자기 job 행 재사용·host 변경 보유 | hold handover uses the receiving job row and host change preserves unconfirmed slots |
| 실제 앱 역할로 UPDATE/DELETE/TRUNCATE 거부·reset GUC 위조 거부 | app role cannot UPDATE append-only tables, DELETE, TRUNCATE or spoof reset |
| 소유자의 이력 덮어쓰기 거부·updated_at 단조 증가 | even the owner cannot overwrite immutable evidence/history, and updated_at increases monotonically |
| subagent 버전·종료 세션 불변 | subagent versions and closed Runner sessions cannot be overwritten |
| 초기화 설정 유지·삭제, GitHub/auth 보존·큐·보유 snapshot | reset keepSettings=true/false deletes project data, queues cleanup and preserves GitHub/auth (2건) |
| 초기화 중간 실패 전체 rollback·기준 커밋 없는 정리 | reset rollback is atomic and omits repository cleanup without a base commit |
| epoch SHARE↔UPDATE 경합 | reset waits for epoch SHARE lock and refuses stale epoch after reset |
| demo 운영 URL 거부 | demo is refused for production before connecting |
| demo 실제 비-test DB 연결 거부 | demo also refuses a non-test connection even when the supplied URL is a test URL |
| P 원문 fixture 대조·12 Task·10 정의·재실행 거부 | demo loads exactly P twelve tasks, dependencies, checklists and ten SUB_MOCK definitions |

기존 `migrate.db.test.ts`의 빈 DB up·반복 적용·PostgreSQL 16·개발 DB 보호 테스트도 전체 DB 명령에서 통과했다. 실패 기대 테스트는 실제 PostgreSQL SQLSTATE와 권한 거부를 확인하며, 초기화 rollback은 reset_log INSERT 트리거 실패를 주입한다.

## 통합 시 주의·미구현

- 앱 연결용 LOGIN의 생성·비밀번호·`awbs_app` 역할 부여와 API 연결 전환은 배포/서버 작업에서 수행해야 한다. DB 패키지의 migration 연결은 소유자다. `lock_epoch` 후 프로젝트→Task→job/hold 순서의 잠금과 모든 변경 경로의 epoch 확인은 M2 Service 책임이다.
- M2/M4의 실제 Runner 정리·파일 삭제·GitHub 작업·reset_log 정리 완료 갱신은 구현하지 않았다. 이 작업은 정리 payload와 큐를 원자적으로 남기는 DB 부분까지다. cleanup 완료 갱신은 제한된 전용 DB 함수/권한으로 연결해야 한다.
- 운영 가동률, 재조정 임계값, 동시 실행 자원 상수·하위 Agent 예산은 미승인 또는 관측값이므로 system seed에서 null/미생성이다. 서비스는 설정·관측을 확보한 뒤 사용해야 한다. 하위 Agent 실제 v1은 M5-06이다.
- JSONB의 TypeBox 쓰기 검증은 M1-02/M2에 연결한다. demo AC는 P의 문자열 배열 원형을 보존한다. data-model의 given/when/then/method 표기를 향후 API가 구조화한다면 demo와 공통 계약을 통합할 때 함께 맞춰야 하며, 여기서는 내용을 추정해 분해하지 않았다.
- 운영 데이터·실제 CLI·외부 서비스는 검사하지 않았다. 유료 CLI 호출, sudo, push, master 병합, prototype/·docs/ 수정은 없었다. verum 자원과 포트 25432 및 기존 awbs 컨테이너·볼륨은 접근하지 않았다.

## 공용 파일 변경·원본 대조

- DB 패키지 외 변경은 `agent-wbs/pnpm-lock.yaml`(Drizzle 생성 도구 drizzle-kit 0.31.11 devDependency 및 하위 의존성)과 `agent-wbs/pnpm-workspace.yaml`의 `allowBuilds: { esbuild: true }` 두 줄뿐이다. pnpm 12가 승인되지 않은 esbuild postinstall로 재현 설치를 거부해 필요한 패키지만 허용했다. root package scripts, shared index와 타입은 변경하지 않았다.
- DB 자체 index에는 schema namespace와 seed 함수만 export했다. 공통 enum·fixture 타입은 DB 디렉토리에 두었다.
- P의 Codex Large/Mini·4단계 effort와 옛 CLI 버전은 운영 기준으로 가져오지 않고 owner Q-06/Q-12를 적용했다. SUB_MOCK의 down migration 문안은 demo 원문에만 남으며, 운영 되돌림은 data-model §6의 forward migration/백업 복원 기준이다. 이 차이는 이미 owner 결정·architecture D-24/D-26 및 계획 §6에 명시되어 있다.
- 그 밖에 새 owner 결정이 필요한 원본/계획 불일치는 발견하지 않았다. AC 표현 통합 주의는 위에 명시했다.
