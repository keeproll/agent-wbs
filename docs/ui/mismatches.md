# 불일치·죽은 동작·미결 사항

판정 우선순위는 가이드 3–5줄대로 **가이드 우선**이다. 아래 `원본`은 Main.dc.html, `가이드`는 Agent-WBS-설계의도-및-구현가이드.md 줄 번호다. 제품 코드를 수정한 보고서가 아니다. 단순 Mock 교체 작업과 실제 모순을 구분했다. 브라우저 재현은 환경 제한으로 하지 못했고, `VM 확인` 표시는 [probe.mjs](probe.mjs)에서 원본 로직을 실행해 확인한 결과다.

## 가이드 자체의 범위·결정 미결

가이드 1127–1156은 Completion Gate 승인 자동화, 진행률 가중치 확정, 허용 상태전이표, CLI Effort 매핑, 실행중 메시지 주입지원, CLI 관측검증/WSL cgroup, 초기화 원격정리, 배포서버, 계약형식, SMTP계정, Telegram 야간정책을 미결로 남긴다. UI 샘플 숫자·버튼으로 이 결정을 대신하지 않는다. 가이드256은 GitHub 원격 정리를 확정했는데1139(미결7)은 여전히 원격정리여부를 미결로 적어 정리가 필요하다. 정합성 점검도 실제서비스에서는 제거·서버테스트 이전(94)과 화면에 정합성만 남김(346)이 함께 있으므로 제품노출 여부를 확정해야 한다.

이번 조사에서는 위 미결을 임의 확정하지 않았다. 구현 판정자는 이 목록의 결정을 완료 증거와 함께 붙여야 한다. 사용자 인증·다중 프로젝트·Runner 내부 UI·실시간 세션관찰은 범위 밖(1129–1132)이며, 예시 설계의 다중저장소/이벤트기술은 Agent WBS 자체 스택 요구가 아니다(154–155).
