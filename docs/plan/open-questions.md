### Q-09 GitHub
- 출처: G L219(private·main), L468·L1039(int 필수·보호 규칙 이중 방어 **확정**), L235·L242·L257(최초 커밋·입력 push·되돌림 push). 필수 검사와 이 push들을 함께 쓰려면 우회 범위가 필요하고 요금제에 따라 규칙 지원이 다를 수 있다(확인 필요).
- **확인된 사실(2026-11-25, coordinator 확인)**: 현재 요금제의 private 저장소에서 보호 규칙 API와 ruleset API가 모두 **403**이다. 개발 저장소 `https://github.com/keeproll/agent-wbs`(private)는 M0까지 병합한 내용이 `origin/main`에 올라가 있다. 이 저장소는 **개발용**이며 시험 저장소(Q-10)는 별도다.
- 따라서 이 요금제에서는 아래 보호 선택지 A·B를 적용할 수 없다. 보호 규칙을 쓸 수 있는 시험 저장소/요금제 확보 또는 owner의 범위 변경은 **미결**이며, M4-06 보호 실증과 M7-02 확정은 그때까지 닫지 않는다.
- 병합은 [contracts §4.1](contracts.md#41-시도-1회)의 strict + 예상 head 병합 API 단일 경로. 일반 병합 자격 증명은 우회 불가.
- 선택지(보호): (A) owner만 입력 push 우회, 최초 생성·초기화 되돌림은 **별도 시스템 커밋 자격 증명**만 우회 / (B) 시스템 커밋도 PR로 만들고 owner가 GitHub에서 승인(초기화가 자동으로 끝나지 않음). CODEOWNERS 검토와 `.agentwbs/` 되돌림을 함께 만족하려면 둘 중 하나가 필요하다. 보호 규칙 없이 Runner 검사만 하는 것은 **G 충족이 아니므로** 선택지에서 제외(owner의 명시적 범위 변경 필요)
- 선택지(인증): (가) `gh` 로그인 / (나) 저장소 한정 fine-grained 토큰
- **추천: A + (나).** 필요한 입력: 시험 저장소 주소, 요금제, 인증, git-lfs 필요 여부. 이 PC에는 `gh`·`git-lfs`가 설치되어 있다.
