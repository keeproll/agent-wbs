## Q-01 로그인과 LAN 접근
- 출처: G§8 L877 「팀장 세션」, G§11 L1132 「인증·권한 체계 범위 밖」, G§4.14 L544 LAN 주소 권장. P에는 로그인 화면이 없다. 모순: LAN에 열면 누구나 초기화·비밀값 설정을 할 수 있다.
- 선택지: (A) 기본 loopback만, CLI가 발급한 1회용 링크로 세션 생성. LAN은 비밀번호를 설정한 경우만 열고 최소 로그인 화면 추가 / (B) 항상 비밀번호 로그인 / (C) 인증 없이 LAN 개방
- **추천 (기본): A.** 단일 사용자 전제를 지키면서 LAN 위험을 막는다. LAN을 쓰려면 프로토타입에 없는 로그인 화면 1개를 승인해야 한다.

## Q-02 완료 승인과 병합 순서
- 출처: G§11 미결 1(L1143), G§5.5 L665 「팀장 승인 완료」, G§4.13 L475 「검증 PASS 후 병합 대기열」·L491 「완료는 ② 통과·PR 병합 후」, G§1.2 L120 「개입 최소화」. P는 `approved`를 **착수 승인**으로 쓰고(L3298, L3777, `Sel.gate` L3689) 마지막에 팀장이 「완료 처리」를 누른다(`completeTask` L5389). 완료 승인을 병합 전에 받는지 후에 받는지 정해져 있지 않다.
- 선택지: (A) 승인 조건 = 착수(계획) 승인. 나머지 Gate 조건 PASS → 자동 병합 대기열 → 병합 → 서버 자동 완료 / (B) 병합 **전** Task마다 팀장 완료 승인 / (C) 병합 후 팀장이 「완료 처리」(P와 같은 버튼)
- **추천 (기본): A + 정책 스위치로 B 선택 가능.** P의 완료 버튼은 자동 완료가 멈춘 경우의 재판정 버튼으로 유지한다. C는 이미 main에 들어간 코드를 승인하는 순서가 된다.

## Q-04 자동 시작 · 자동 재작업 · 재시도 한도
- 출처: G§1.2 L119-120 「실제 작업은 Agent」·「개입 최소화」, G§5.3 L634 「실행 요청 가능」, G§4.14 L513 「재시도 한도 초과」(값 없음), G§4.6 L319. P는 개발 시작·재작업 지시가 팀장 버튼, QA는 자동(`registerDev` L5883, `sendRework` L5921).
- 선택지: (A) ready면 자동 시작, QA FAIL이면 자동 재작업, 자동 재시도는 시도 실패 2회·QA 재작업 3회까지 이후 팀장 / (B) 시작은 팀장 버튼, 이후 자동 / (C) P처럼 시작·재작업 모두 버튼
- **추천 (기본): B로 구현하고 A를 정책 스위치로 제공**, 한도 2·3회는 [추정] 초기값. 비용이 드는 외부 호출이므로 처음부터 완전 자동은 피한다.

## Q-08 Agent 세션 격리

## Q-09 GitHub 저장소 · 인증 · main 보호
- 출처: G§4.2 L217-219(private·main), G§4.13 L468(「agentwbs/int 통과」 필수), G§4.2 L242·L246(입력은 main 직접 push·웹 편집), L235(최초 생성 커밋), L257(초기화 되돌림 커밋을 main push), G§9.5 L1039-1040. **모순**: 필수 status check가 걸리면 입력 push·최초 커밋·되돌림 push도 막힐 수 있다. 토큰 권한에 관리자 권한이 없어 Runner가 보호 규칙을 설정할 수 없다. private 저장소의 보호 규칙은 GitHub 요금제에 따라 쓸 수 없을 수 있다(확인 필요). 이 PC에는 `gh`·`git-lfs`가 없고 이 저장소에는 remote가 없다.
- 선택지(보호): (A) owner가 ruleset을 직접 만들고 owner와 Runner 계정만 **우회 허용**, Runner는 지정된 2종 커밋 외 직접 push 금지를 코드로 강제 / (B) 모든 변경을 PR로(입력·초기화 포함) / (C) 서버 규칙 없이 Runner 검사만
- 선택지(인증): (가) `gh` 로그인 / (나) 저장소 한정 fine-grained 토큰
- **추천: A + (나).** 사용 요금제에서 ruleset이 안 되면 C로 시작하고 위험을 화면·문서에 표시. 필요한 것: 저장소 주소, 요금제, 토큰 발급, git-lfs 필요 여부.
